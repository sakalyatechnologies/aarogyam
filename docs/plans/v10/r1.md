# r1: mobile shared adapts to the backend contract

Changes (one commit each):
1. Family uses generated `FamilyLink/FamilyList/NewFamilyLink/FamilyMember/FamilyOfFields/PhoneMatches`; `FamilyDtos.kt`, the `notSupported` branches and the `family_of` JSON splice are gone. `ServerCaps.family` defaults on (`markFamily` kept, harmless).
2. Desk collect: `recheck` reads `GET /invoices/{id}/collect-summary` (`ClinicApi.collectSummary`), sends `patient.id`, never sets `issueFirst` (server issues a draft on payment; allocate `min(amount,total)`); `DueBill.upi` (`CollectUpi`) is filled once the summary is read, for the QR and open-app link.
3. Profile photo: `ClinicApi.putPatientPhoto` (`PUT /patients/{id}/photo`, field `file`); `PatientFileSender` sends kind `photo` there, rejects over 2 MB as `photo_too_large`; the signature stays a `consent` attachment.
4. Today schedule drops `no_show` as well as `cancelled`; `no_show` maps to no desk state (not `Left`), so a phone lookup still offers check-in.

Tests: DeskCollectRaceTest (collect-summary, no `/issue` for a draft, upi on state), PatientFileSenderTest (PUT field `file`, signature as attachment, over 2 MB), TodayStateHolderTest (no_show/cancelled hidden), PatientStateTest, ServerCapsTest, IntakeFormHolderTest.

Gaps: `DueBill.upi` is only set after a send attempt (the recheck), so iOS cannot draw the QR before then; the 409 refetch and the list load still use `GET /invoices/{id}` (`billing.read`). The desk holder still needs `billing.read` to list bills. Swift unchanged (no removed names used). `ServerCaps.markFamily` calls remain in older tests.
