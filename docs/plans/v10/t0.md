# v10 T0: retarget and seams (handoff)

Branch `feat/v10` in `~/project/wt-v10`. Scope: `mobile/**` only. Later workers branch from the T0 merge commit and must not edit `AppGraph.kt`, `OutboxEntry.kt`, `MainTabs.swift`, `RootView.swift` or `NavModel.kt`.

## What changed

**Compile against main's spec (57 errors fixed)**
- `close` is gone. `ClinicApi.finishVisit(visitId, FinishRequest): Outcome<FinishedVisit, ApiError>` calls `POST /visits/{id}/finish` (`api/VisitNoteCalls.kt`).
  - `finishBody(followUpOn, note, feePaise)` in `visit/VisitModels.kt` always sends `queue_status = ready_to_bill` (plan D8). The old follow-up reason becomes `note` (main's `note` is the follow-up reason, or the bill note when there is only a fee). `follow_up_reason` is dropped. `sign_notes` is left at the server default (true).
  - `VisitStateHolder.closeWith(...)` keeps its signature and now finishes.
- **Outbox migration (R3).** `OutboxKind.VisitClose` and the `CloseJob` payload are unchanged on disk, so entries saved by older builds decode as before. `VisitWriteSender` sends them through `finishVisit`, with `reason` mapped to `note`. Test: `outbox/V10SeamsTest.a_close_saved_by_an_older_build_is_sent_as_finish`.
- `VisitShare` is now `VisitLink`; the body is `ShareRequest(channel = "link")`. `VisitShareStateHolder` builds the URL as `origin + "/shared/" + token`.
- `NotifiedQueueToken` is `{id, number}`. `AlertRow.tokenNumber` takes `number`; `patientNumber` and `doctor` stay in `AlertRow` but are always null (notifications never carry names).
- Family and payment proof use hand-written DTOs in `config/caps/` behind `ServerCaps`:
  - `FamilyDtos.kt`: `FamilyLink`, `FamilyList`, `NewFamilyLink`, `FamilyMember`, `PhoneMatchesFamily` (items plus `family_group`), `FamilyOfBody`.
  - `ClinicApi.family/addFamily/removeFamily` answer `Outcome.Failure(ApiError.local(NOT_SUPPORTED "not_supported"))` while `ServerCaps.family` is off, and send nothing.
  - `lookupByPhone` now returns `PhoneMatchesFamily` and marks `ServerCaps.family` when the answer has a `family_group` key.
  - `registerWalkIn(request, familyOf: FamilyOfBody? = null)` merges `family_of` into the JSON body only when the flag is on. `WalkInRequest` no longer carries it.
  - `ClinicApi.recordPayment(payment, key, attachmentId = null)` merges `attachment_id` only when `ServerCaps.paymentProof` is on. It decodes the answer as JSON first and marks the flag when `attachment_id` is present. `DeskPayment.canProof` also needs the flag, so the proof button disappears until the server ships it.
- Test fixtures follow main's new required fields: Appointment `patient_type`, ChartEntry `canals`/`in_progress`, LabOrder `late`/`pipeline_stage`, TodayCounts `called`/`ready_to_bill`, TodayResponse `completed_visits`, ShareLink `channel`. commonTest already used `kotlinx.io.IOException`.

## ServerCaps (`config/caps/ServerCaps.kt`)

`object ServerCaps` with `state: StateFlow<CapsSnapshot>`, getters `family`, `paymentProof`, `notificationAudience`, `walkInReason`, `queueRemind`, `messageStatus`, `mark<Flag>()` setters and `reset()`. Flags never turn off within a session. `capsJson` (internal, `ignoreUnknownKeys`) is the Json for the DTOs.

Only `family` and `paymentProof` have a detection point so far. The other four (`notificationAudience`, `walkInReason`, `queueRemind`, `messageStatus`) have no detector yet: T1 or the owning worker adds a hand-written view and calls `ServerCaps.mark*()` where the field first appears. A flag is global per process, not per clinic.

How to fill a factory: the holder interface is empty. The worker adds members to it, writes the real class in the same file and changes the `internal fun create*(...)` body (same parameters) to build it. The `AppGraph` method keeps returning the interface, so Swift sees the new members through SKIE without an `AppGraph` edit. The filenames end in `Holder` because ktlint requires a file with one class to be named after it. If a holder needs a logger or an extra argument, take `clinic.log` or ask the coordinator; the `AppGraph` signature is fixed.

The stub senders keep their entries waiting (`Retry`, not `Rejected`), so a write saved by a later build is not lost by an earlier one.

iOS (`mobile/iosApp/AarogyamStaff/Screens/`), each an `enum RoutesV10X` with `@ViewBuilder static func hook(graph:clinic:)` returning a zero-size hidden placeholder view. `MainTabs` calls the first four inside one `.background { ... }`; `RootView` calls `Live` after `.id("main-...")`. A screen replaces the body of `hook` (and may add files) with no shell edit.
- `Routes+V10Desk.swift`: `RoutesV10Desk.hook(graph:clinic:)`
- `Routes+V10Intake.swift`: `RoutesV10Intake.hook(graph:clinic:)`
- `Routes+V10Doctor.swift`: `RoutesV10Doctor.hook(graph:clinic:)`
- `Routes+V10Tasks.swift`: `RoutesV10Tasks.hook(graph:clinic:)`
- `Routes+V10Live.swift`: `RoutesV10Live.hook(graph:)`

Empty string catalogs next to the existing tables: `DeskV10.xcstrings`, `IntakeV10.xcstrings`, `DoctorV10.xcstrings`, `TasksV10.xcstrings` (source language `en`, no strings). Add `hi` and `mr` for every key, as the V9 tables do.

## Gaps and notes for the coordinator

- `ServerCaps.family` is global and only turns on after a phone lookup returns `family_group`. A patient opened without a lookup has no family section until then. This is intentional (no fake substitute) but T2 or T7 may want a second detector.
- iOS still draws the family UI and the walk-in family picker unconditionally: Kotlin holders answer `not_supported` and the walk-in submit drops `family_of` while the flag is off, but Swift does not yet hide those controls on `ServerCaps.shared.family`. To hide them, a screen worker reads `ServerCaps.shared.state` (StateFlow). I did not edit those Swift files (V9 screens) in T0.
- The payment-proof upload still happens before the payment when a proof photo exists. The photo cannot be chosen while the flag is off, so this only matters for jobs already queued by an older build (the upload goes up as a patient attachment; the payment omits `attachment_id`).
- `finish` always signs the caller's own draft notes (server default). The doctor's explicit Sign button still works first.
- `VisitHistoryStateHolderTest.a_screen_is_three_requests` is flaky under load (it counts requests right after the first state; failed once, passed on rerun). Not touched.
- `jvmTest` for Chart, Calendar and Booking hangs for 60 s per test when fixtures miss required fields; this is how fixture drift shows, so look there first after a spec regeneration.
