## Wrap up (D8, D9)

`interface FinishVisitHolder` (factory `createFinishVisit(clinic, visitId, scope)` unchanged, AppGraph untouched):
```kotlin
val state: StateFlow<FinishState>
fun attach(sources: FinishSources)          // call when the screen opens, and again after the Rx draft changes
fun pickFollowUp(choice: FollowUpChoice)    // OneWeek 7, TwoWeeks 14, OneMonth 30, SixMonths 182, NotNeeded
fun setFee(paise: Long?)                    // null or 0 = no bill; replaces the prefill
fun setIssueRx(on: Boolean)
fun setOverrideReason(text: String)
fun finish(collectNow: Boolean)
fun backToEditing()
class FinishSources(patientId: String, saveNote: suspend () -> Boolean, saveRx: suspend () -> RxSave,
                    rxDraftId: () -> String?, writes: WriteQueue? = null)
```
`FinishState(followUp, feePaise, hasRxDraft, issueRx, overrideReason, outcome: FinishOutcome, phase: FinishPhase)`.
`FinishPhase`: `Editing`, `Finishing`, `NeedsOverride(alerts)`, `NeedsConnection`, `Queued`, `Failed(reason: FinishFailure, message)`, `Done(summary: FinishedSummary)`.
`FinishedSummary(outcome, invoiceId, invoiceTotalPaise, followUpOn, rxIssued, rxNumber, share: ShareStatus, sharePin, shareToken)`. `Collected` only when `collectNow` and the server returned an invoice (open the A10 sheet on `invoiceId`); otherwise `SentToDesk`.

Behaviour: fee prefilled from `GET /visits/{id}` (sum of `price_paise`, excluding cancelled/error procedures), a doctor edit always wins. Issue Rx is on when a draft exists. Order: `saveNote`, `saveRx` (only when issuing, or a draft exists and the phone is online), then one `POST /visits/{id}/finish` with `queue_status=ready_to_bill` for both buttons, follow-up date = clinic-today + days, `prescription{id, notify_patient=false, share=link, override_reason}`. 409 `allergy_alerts` gives `NeedsOverride`; `finish` does nothing until a reason is set, then retries with it. `visit_closed` gives `Failed(VisitClosed, plain text)`. Offline: with an Rx, `NeedsConnection` (nothing saved for later, nothing sent); without an Rx, `writes.close(...)` (the existing `VisitClose` job, key `visit:{id}`) and `Queued`. A retryable server failure follows the same rule.

## Audio (D4, R9)

Public API for the iOS worker (T9):
```kotlin
fun enqueueAudio(runner: OutboxRunner, files: OutboxFiles, clinicSlug: String, patientId: String,
                 visitId: String?, noteId: String?, bytes: ByteArray, durationSeconds: Int,
                 language: String?, mimeType: String = "audio/mp4"): AudioEnqueue
sealed interface AudioEnqueue { Saved(id), TooLong, TooLarge, FilesFull, QueueFull, Empty }
const val AUDIO_MAX_SECONDS = 600; const val AUDIO_MAX_BYTES = 10 MiB
```
`runner` is `graph.writes.runner`; the files store is the graph's `OutboxFiles`. Call it after the transcript is saved to the note; `noteId` is the note's client id (the sender waits for the note if it is not sent yet: 404/422 retry up to 8 attempts). `language` other than `en-IN`/`hi-IN`/`mr-IN` is sent without a tag, as on the web.

`AudioSender`: multipart to `POST /patients/{id}/attachments` with `id` (entry id, idempotency), `kind=audio`, `note_id`, `visit_id`, `duration_seconds`, `language`, file `voice-note.m4a|ogg|webm`. The existing `uploadAttachment` is JPEG-only with a fixed form, so I added `ClinicApi.uploadAudio` (internal, in AudioSender.kt). Whole-item retry; over 600 s or 10 MiB gives `Rejected(audio_too_long|audio_too_large)` and the file goes; the file is deleted after a successful upload. Logs: entry id and error codes only. The entry has no order key on purpose: a recording stuck on a slow network must not hold the visit's finish (a keyed close waits for every other entry of its key).

## Gaps

- `share` is requested whenever an Rx is issued (`notify_patient=false`, as the Rx sheet does); the web does not. Change in `FinishVisitStateHolder.run` if the desk wants the email.
- English failure messages live in the holder (`FinishFailure` is the key to translate).
- The Rx draft is saved only when issuing or online; there is no test for `saveRx` failure or `saveNote` failure.
- A queued finish carries no Rx and no note text; the offline note is queued by the visit holder ahead of it (same order key).
- Procedure statuses excluded from the fee prefill (`cancelled`, `canceled`, `error`, `entered_in_error`) are a guess; check against the server's status list.
