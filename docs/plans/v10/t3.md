## Public API (for the iOS T8 worker)

```kotlin
interface IntakeFormHolder {
    val state: StateFlow<IntakeForm>
    fun setPhone(typed: String)            // digits kept to 10; +91 / leading 0 drop out
    fun setName(text: String)
    fun setDateOfBirth(text: String)       // "YYYY-MM-DD"; clears age
    fun setAge(text: String)               // digits; clears DOB
    fun setEmail(text: String)
    fun setSex(value: Sex)                 // tapping again clears
    fun toggleAllergy(label: String)       // clears "none known"
    fun toggleNoKnownAllergies()           // clears the picks
    fun setReadAloud(on: Boolean)          // care consent: notice read aloud, patient agrees
    fun setReminders(on: Boolean)          // default true
    fun setSignature(png: ByteArray?)      // PNG bytes from the pad; null = cleared
    fun setPhoto(jpeg: ByteArray?)         // optional, JPEG already resized
    fun setPractitioner(id: String?)
    fun setReason(text: String)            // draw only when state.showReason
    fun setFamilyOf(patientId: String?, relation: String)  // draw only when state.showFamily
    fun saveAndQueue()
    fun reset()                            // clean form for the next patient
}
```

`IntakeForm` (state): the typed fields, `errors: Map<IntakeField, IntakeProblem>`, `submitting`, `submitError: IntakeSubmitError?` (`NeedsConnection`, `NotWired`, `Server(ScreenError)`), `done: IntakeDone?` (`patientId, tokenId, tokenNumber, filesQueued, filesRefused: Refusal?`), reference data (`doctors`, `allergyPicks`, `notice: IntakeNotice(id, version, label, body)` to read aloud), `signaturePresent`, `photoPresent`, `showReason`, `showFamily`.
`IntakeField`: Name, Birth, Phone, Email, Allergies, Consent, Signature, Reason. `IntakeProblem`: Required, Invalid, InFuture. An error clears when its field is edited.

Factory (unchanged): `internal fun createIntakeForm(clinic: ClinicContext, scope: CoroutineScope): IntakeFormHolder`.

## Behaviour

- Validation (inline, all at once): name 2+ chars; phone, when given, a complete Indian mobile; email, when given, shaped like one; DOB (valid, not future) or age 0..120; allergies chosen or "none known"; `readAloud` ticked; signature present. Sex, photo, practitioner, reason are optional.
- Save & queue: validate, then offline gives `NeedsConnection` (nothing sent or queued, form and bytes kept), else exactly one `POST /walk-ins` through `registerWalkIn` and the existing `walkInRequest` builder (new fields are added with `.copy`: `date_of_birth`, `email`, `notice_id` of the newest published notice, `reason`). Then the photo (`photo`, "Profile") and signature (`consent`, "Signature") are enqueued as `PatientFile` entries with client v7 ids, the file bytes written to `OutboxFiles` as `<id>.jpg` / `<id>.png`. A failed walk-in queues nothing. If the files cannot be saved (cap or queue full) the patient is still registered and `done.filesRefused` says why.
- Flags: `reason` is sent through the generated `WalkInRequest.reason`, only while `ServerCaps.walkInReason` is on; the holder calls `ServerCaps.markWalkInReason()` at start (G6 is in the spec, as the coordinator advised). `family_of` goes only while `ServerCaps.family` is on. The flags are re-read on each `saveAndQueue`.
- Sender: `POST /patients/{id}/attachments` through `ClinicApi.uploadAttachment`, entry id as the client `id`, kind and label from the job. Whole-item retry (the file is kept until the server has it, then deleted). `clinic_not_open` waits; missing file or a 4xx is rejected. Logs hold error codes only.

## Gaps

- `ClinicApi.uploadAttachment` hard-codes `image/jpeg` and the file name `photo.jpg`, so the signature PNG goes up with a JPEG content type. If the server sniffs or rejects it, change the helper to take a mime type (not in my files).
- Practitioner is optional, and the care consent is a single "read aloud" tick (reminders is separate); a clinic with no published notice sends no `notice_id` and the server records its template.
- The aggregate walk-in answer carries no allergy/consent errors; a duplicate phone is registered as new (as the V9 walk-in does); the lookup-to-intake handoff is the screen's job (call `setPhone`).
