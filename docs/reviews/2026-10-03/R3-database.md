# R3 — Independent principal review of the Aarogyam data model (3 Oct 2026)

Verdict: the product-level model is strong (org-aware composite FKs — verified that FK checks bypass RLS, so single-column FKs would accept another clinic's row; typed share-link FKs; superseding corrections; server-issued numbers; non-unique phones). Not ready for M1 as written: Supabase exposure, roles/ownership, pre-tenant reads and the two log tables are undefined or contradictory. Two measured facts change conventions: under RLS, enum equality and trigram/ILIKE/JSONB/range filters are not leakproof (the index serves only `org_id`); full-row audit costs ~7× changes-only. "Verified" = reproduced on local PG17.

## Proposed M1 conventions
- Schemas: `app` (functions), `aarogyam` (tables), `audit` (logs), `private` (internal). Nothing in `public`. Extensions in `extensions`. Schema-qualified DDL.
- Clinic tables: `org_id uuid not null default app.tenant_id()`, `id uuid not null default app.uuid_v7()`, PK `(org_id, id)`; composite FKs `ON DELETE RESTRICT` (or `SET NULL (col)`); every unique key starts with `org_id` (a bare unique key leaks other clinics' rows — verified); index every FK; text + CHECK statuses; `bigint` paise ≥ 0; local days in clinic timezone.
- One file per table: table, RLS `to app_user using (org_id = (select app.tenant_id())) with check (…)`, grants (DELETE only for ephemeral tables), meta + audit triggers, indexes, COMMENT with sensitivity and offline class.
- Definer functions: `search_path=''`, qualified names, `revoke execute from public`, one grantee, tests.
- Migrations additive, `lock_timeout` set, run as `postgres` in session mode.
- CI lint: RLS + policy on every table; keys start with org_id; clinic-aware FKs; FK indexes; audit trigger everywhere; no privileges for anon/authenticated/PUBLIC; pinned search_path on definer functions; no DELETE on finalizable tables; cross-clinic tests; migrations as a Supabase-shaped non-superuser.

## Proposed M1 files
1. `0001_schemas_extensions.sql` — schemas; btree_gist, btree_gin, pg_trgm; revoke default privileges (tables, sequences, functions).
2. `0002_roles.sql` — NOLOGIN `app_user`, `app_worker`, `app_console`; LOGIN NOINHERIT `aarogyam_api`, `aarogyam_worker`, `aarogyam_console` each granted its role `WITH SET TRUE, INHERIT FALSE`; per-role timeouts and search_path; schema USAGE.
3. `0003_app_functions.sql` — `tenant_id()`, `user_id()`, `request_id()`, `actor_kind()` (STABLE SQL, no SET clause), `uuid_v7()`.
4. `0004_row_guards.sql` — `set_row_meta()`, `forbid_change()`, `freeze_when()`.
5. `0005_audit.sql` — `audit.audit_config`; partitioned `audit.audit_events` (default + 12 months); definer `app.audit_row()` (changes only, masks); `app.ensure_partitions()`.
6. `0006_iam.sql` — users, devices, sessions (own row; display fields of same-clinic people).
7. `0007_tenancy_orgs.sql` — organizations, org_domains (normalized, verified), branches (GSTIN, state, one default), org_settings.
8. `0008_tenancy_access.sql` — global role templates + permission catalog, roles, role_permissions, memberships, membership_branches, invitations.
9. `0009_number_sequences.sql` — table + `app.next_number()` upsert.
10. `0010_access_log.sql` — partitioned, nullable actor, no FKs, insert-only.
11. `0011_pretenant.sql` — `resolve_host`, `authorize`, `ensure_user`, `accept_invitation`, `my_clinics`, console `create_clinic` (organization, domain, default branch, settings, roles, owner invite, number series).
12. `0012_private.sql` — unlogged `private.sakalya_rate_limits`.
