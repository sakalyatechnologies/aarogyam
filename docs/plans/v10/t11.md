# T11 live banners

What: an app-wide banner (top overlay, any tab) when a new `patient_waiting`, `send_in` or `collect_payment`
notification arrives. Token number only, no patient names. Haptic success; `send_in` also plays system sound 1007.
Auto-dismiss at 6 s, tap to dismiss, VoiceOver announcement, Reduce Motion fades instead of sliding.

Files: shared `live/LiveBanners.kt` (LiveBannerHolder polls unread notifications while in front; first load only
records ids), `NotificationKinds.kt` (`queue_token`), `IosV10.kt` (`liveBanners`), iOS `Screens/LiveV10/*`,
`LiveV10.xcstrings` (en/hi/mr), `Routes+V10Live.swift`, `RootView.swift` overlay, `DoctorWaitingCard.swift`
(inline banner and haptic removed).

Tests: `LiveBannerHolderTest` (first load, new send_in, repeat id, handled, other kind, background),
`LiveV10Tests`, `StringCatalogTests` table list.

Gaps: the holder also exposes `state` (boxed banner) because ScreenHost cannot take a nullable flow. Gradle check
last passed before that change; it needs a re-run. The `dv10.waiting.banner` string is now unused.
